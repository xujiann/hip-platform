# HIP 平台生产部署手册

## 环境要求
- 服务器：2 台起（应用 + 数据库），4C8G 以上；操作系统 Linux（或信创麒麟）
- JDK 21（Temurin/信创 JDK）、PostgreSQL 16（或达梦/金仓 PG 兼容模式）、Node 仅构建期需要

## 部署步骤
1. **数据库**：`deploy/docker-compose.yml` 起 postgres+redis，或使用已有实例；创建库 `hip`、用户 `hip`
2. **后端**：`mvn clean package -DskipTests` 产出 `server/target/hip-server-*.jar`
   - 环境变量覆盖敏感配置：`SPRING_DATASOURCE_URL/USERNAME/PASSWORD`、`HIP_SECURITY_JWT_SECRET`（必须更换）
   - `java -jar hip-server.jar`（首次启动 Flyway 自动建表 V1-V17，并创建 admin/admin123——**上线立即改密**）
   - MLLP 设备接入端口 2575（`hip.integration.mllp-port`），防火墙仅对 LIS 网段开放
3. **前端**：`cd frontend/shell && npm ci && npm run build`，`dist/` 交给 Nginx：
   ```nginx
   location /api { proxy_pass http://127.0.0.1:8080; }
   location / { root /opt/hip/dist; try_files $uri $uri/ /index.html; }
   ```
4. **验证**：`python tools/e2e-outpatient.py`（改 BASE 为生产地址的测试库演练）

## 安全基线（等保，产品化一期落地）
- **JWT 密钥**：设置环境变量 `HIP_JWT_SECRET`（≥32 位随机串，如 `openssl rand -base64 48`）；
  未设置时回落开发占位值——生产/试点严禁使用占位值
- **默认口令**：初始化用 `tools/init-hospital.py`（配置里 `adminNewPassword` 必填，
  执行末尾强制更换 admin 口令并验证）；**生产库严禁运行 `bootstrap-demo.py`**（演示账号 Demo1234）
- 密码策略 8 位字母+数字，5 次失败锁定 15 分钟；90 天更换提醒
- HTTPS：nginx 反代终止 TLS（`frontend/shell/nginx.conf` 基础上加 443 server 块与证书）
- 写操作全量审计（sys_audit_log），建议对接日志外发
- 患者端接口与院内接口角色级隔离（ROLE_PORTAL）

## 医院初始化（产品化一期）
1. Flyway 随首次启动自动建库（V1-V43，含平台必需与行业基线种子）
2. 复制 `tools/init-templates/hospital.example.json` 按院填写：院名、模块开关、科室病区床位、
   业务账号、字典 CSV（药品/收费项目/医保对照）
3. `python tools/init-hospital.py 配置.json --base http://<host>:8080`（幂等可重复）
4. 未采购模块在配置 `modules` 置 false——菜单与 API 双关闭（ModuleGate）

## 数据迁移
- 患者：`tools/import-patients.py`（模板 `tools/migrate-templates/patients.csv`，同证件号幂等）
- 药品/收费目录：init-hospital 字典 CSV 或 `POST /api/masterdata/drugs|charge-items/import`
- 医保对照：`POST /api/insurance/catalog/import`（模板 `tools/migrate-templates/yb-catalog.csv`）
- 老系统保留只读至少 1 年，切换演练至少 2 轮

## 回滚
- 应用：保留上一版 jar，直接替换回滚（Flyway 向前兼容，不自动降级——发版前备份库）
- 数据库：每日 pg_dump 全量 + WAL 归档

## 部署形态定型（v17 试点收尾）

- **试点（本机/Windows）**：裸机形态——jar + WSL PostgreSQL + nginx，`spring.profiles.active=pilot`
  （application-pilot.yml：连接串/慢阈值/MLLP 均走环境变量，日志滚动 50MB×30）
- **院方服务器（Linux）**：deploy/docker-compose.full.yml 全栈（compose config 校验通过；
  CI 的 postgres 容器工作流即容器路径的持续验证）
- 两形态共用同一 jar 与 dist，仅编排差异

## 备份自动化（三十七期补充）

- 每日自动备份：管理员 PowerShell 执行 `tools\schedule-backup.ps1` 注册任务计划 `HIP-DailyBackup`（每日 02:30 调 `tools\db-backup.ps1`）
- 恢复演练：`tools\db-restore.ps1 -File deploy\backups\hip_xxx.dump`（默认恢复到校验库 hip_restore_check，不动生产库）
- 演示/验收数据：`python tools\bootstrap-demo.py`（幂等）
- 投标响应底稿：`python tools\export-deviation.py` → docs/验收/技术偏离表.csv
