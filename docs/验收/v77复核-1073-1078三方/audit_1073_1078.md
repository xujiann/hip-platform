## 四、1078★ 子要求清单与逐条判定

拆分：①拥有授权能力；②科室/个人范围模板须授权到科室或个人后才能使用；③新建时自动授权给构建科室或构建人；④其他科室/个人想用须将模板授权给对应科室或个人。

### 4.1 自动授权的实现——显式行还是隐含（主控问题 ①）

**两者并存，且可见性对本科/本人并不依赖那条显式行**：

- 显式：`/scoped` 建模板后 `autoGrant`（`EmrTemplateService.java:391, 399-405`）——DEPT 写 (DEPT, dept_id)，PERSONAL 写 (USER, owner_id)，`granted_by` = 建者。实测 #37 建成即有 grant #2 (DEPT,1，授予人 演示门诊医生)；#38 有 grant #3 (USER,15)。旧通道 `POST /emr-templates` 对 deptId 非空也写一条 DEPT 行（`MedTechController.java:505-510`；实测 #40 grant_count 1）。
- 隐含：`canSee` 对 DEPT 另有 `a.deptId().equals(t.deptId())`、对任何 scope 另有 `owner_id = 本人`（`:172-176`），所以**即使没有授权行**，本科室/本人也能看到。证据：库中历史 DEPT 模板 #1–#32（V138 前建、`created_by` 空）**一条授权行都没有**，维护页「授权」列显示 0 个，但 doctor01 照样在下拉里看到它们（V138:48-53 的回填只改 scope，不补授权行）。
- 「撤销」语义差异：自授权那一行**不允许撤**（`revoke:522-541` → 4065，实测两种都拒：「不能撤销模板对自身科室/创建人的授权…如需收回请停用模板」）。因此对构建科室/构建人而言，授权行是**只增不减的记录**（可追溯"谁、何时授的"），而"收回"的唯一手段是停用整张模板——与参数"自动完成授权"不冲突，但须作为限定写出（评委会问"能不能把科室模板从本科收回只留给某人"——答案是不能，只能停用后另建个人模板）。

### 4.2 两种粒度、撤销、被授权方在哪看到（主控问题 ②）

| 项 | 实现 | 实测 |
|---|---|---|

| 授权到个人 | `{granteeType:'USER'}`；候选取 `sys_user where enabled`，按 real_name 模糊 | doctor01 把 #38 授 USER 19 → tech01 可见 #38；admin 仍不可见；本科其他人仍不可见（JUnit） |

### 4.3 全院/全局"人人可用"与参数是否冲突（主控问题 ③）

不冲突。参数只对「使用范围为科室或个人的模板」要求授权；全院/全局不在其列。实现：GLOBAL/HOSPITAL 不写授权行、恒可见（§3.5）。"人人"= 持有 EMR_TPL_ROLES 五角色之一的登录人（cashier01 → 1005）；病历书写者全在其中。须限定一句：「全院与全局模板不走授权、对全部可书写病历的角色可见」。

### 4.4 谁能授权（主控问题 ④）

`grant()`/`revoke()` 均 `requireEditable` → `canEdit`（`:201-207`）：

| scope | 可授权/撤销的人 | 实测 |
|---|---|---|
| PERSONAL | **仅本人**（管理员不能，因为看不见） | admin 对 #38 授权 → 4066 |
| DEPT | 创建者本人 或 ADMIN | admin 对 #37 授 USER 19 → 0；tech01（被授权科室的人）→ 4066 |
| GLOBAL/HOSPITAL | 仅 ADMIN | doctor01 PUT #35/#36 → 4066 |
| 历史 DEPT 模板（owner 空，#1–#32） | 仅 ADMIN | 推演：`canEdit` DEPT 分支 `userId.equals(ownerId)` 对 null 为 false |

系统**没有"科室主任"角色**（`sys_role` 九个角色：ADMIN/DOCTOR_OUTP/CASHIER/PHARMACIST/NURSE/TECHNICIAN/QUALITY/OPERATION/INTERFACE），本科室非创建者的同事也**不能**授权科室模板。须限定：「科室模板由创建者或系统管理员授权，个人模板仅本人授权」。

**判定 ①②③④：满足**（带 §九 限定），但 §七 N1 把"非管理员建不了全院模板"这条防线从旧通道绕开了——见裁定。

## 九、审计意见与须标注项

### 1073★：**上调（正偏离/无偏离）——以 N1、N2 两条旧通道收口为前置；若主控决定不动旧通道，则维持部分响应**

理由：参数两个原子（权限差异检索、四级范围）在全部 UI 路径与可见通道 API 上成立，JUnit 逐格钉死，本轮五账号 HTTP 实测与矩阵一致；全局/全院无差别是"四级名义三级行为"，属限定而非缺项（参数只要求"分为"四类，未要求各类行为互异）。**但** N2 让"他人个人模板不可见"在 API 层为假、N1 让"全院模板仅管理员"在 API 层为假——反驳者（数据口径镜头）一条 curl 即可推翻说明中的两句真话。两条修法都在端点内（N2 加一个 where 分支即可，现有断言不受影响；N1 需同时照顾三个 `@WithMockUser` 单测，见 N1 行），不改请求返回形态；修完再走复核才是零推翻。

### 1078★：**上调（正偏离/无偏离）——同样以 N1 为前置（N1 直接打穿"非管理员建不了全院模板"），N3 建议同批修或写进限定**

理由：授权到科室/个人、新建自动授权、授权后可见、撤销、只放大可见不放大维护，全部有源码 + JUnit + 本轮 HTTP 实测；自授权不可撤销是设计取舍（收回=停用），与参数"自动完成授权"不冲突；"谁能授权"参数未限定，系统口径（创建者/管理员；个人仅本人）须写明。

### 两条须标注的限定句（落说明时逐句带上）

1. 全局与全院两级**可见性与维护权相同**（人人可见、仅系统管理员维护），全局用于标识平台/集团级模板；**平台不预置任何模板**，四级模板均由院方于实施期建立。
2. 系统管理员可见全部科室模板，**但看不到他人的个人模板**，也不能对其授权。
3. 科室模板由**创建者或系统管理员**授权与维护，个人模板**仅本人**；被授权的科室/个人可查看、套用、复制，不能修改、停用或再授权（授权只放大可见范围）。
4. 新建时自动授予构建科室/构建人的那条授权**不可撤销**；要收回模板只能停用（软停用，历史病历可追溯）。
5. 全院与全局模板**不需要授权**，对全部可书写病历的角色（管理员、门诊医生、质控、护士、医技）可见。
6. 若 N3 不修：「修改模板作用范围时既有授权保留，须在授权对话框自行撤销」。
7. 1078 说明中的「在模板维护页」保留（维护页菜单授 ADMIN/DOCTOR_OUTP/QUALITY；护士与医技只能被授权、不能进维护页）。
8. 1074 同批改「四级」。
