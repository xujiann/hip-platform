### 1073★

参数原文：「能够依据权限的不同检索到不同的模板，依据应用范围模板分为全局模板、全院模板、科室模板、个人模板。」
语法：两个并列谓语——**依据权限的不同检索到不同的模板**（主语是"系统/使用者"，谓语是"检索到不同"，条件是"权限不同"）；**依据应用范围分为四类**（分类谓语，列举四个名词）。

| # | 原子 | 判定 | 一句话 |

| A1 | 「权限」在本系统指什么 | 做实（须标注口径） | 权限 = 控制器角色门槛（五角色）× 本人科室 × 是否 ADMIN × 授权表；不是单纯"角色"，也不是菜单权限 |
| A2 | 「检索到不同」——结果是否真随之不同 | 做实 | 五账号 `/visible?type=EMR`：admin 37 张 / doctor01 35 / tech01、nurse01、quality01 各 1（§二） |

1. **D1 「权限」我拆成"系统所认的权限"与"评委所想的权限"两层**。审计者 §3.1 的三层叠加是对的，但漏了一句：**可见性对非管理员不看角色**——doctor01/tech01/nurse01/quality01 四个不同角色，可见集合的差异完全来自 `dept_id` 与授权表（nurse01/quality01 无科室所以只见 #34 全院模板）。评委若理解"权限"为"角色权限"，会问"质控和护士为什么看到的一样"。说明里要把"权限"落成「所在科室、是否系统管理员、授权」三个词，不要让"权限"裸奔。

## 结论

**1073★：不推翻但须标注。** 「依据权限检索到不同模板」在三入口与老通道 API 上成立（修后老通道 id 集与 `/visible` 逐一相等，五账号五种结果）；「分为四级」四值真实存在、可建可筛，全局与全院行为相同属限定（L1）而非缺口；没有子要求在 HEAD 仍没做实，审计者没有把"没做"说成"做了"。须标注：L1、L2、句 3 的"权限"落成科室/管理员/授权、句 5 改"仅本人与被授权个人"。

**1078★：不推翻但须标注。** 授权能力、两粒度、他科/他人须授权、新建显式自动授权行、撤销、只放大可见不放大维护，源码 + HTTP 逐条复现；N1/N3 前置在 HEAD 已闭合（回归点"只改名不清授权"也核过）。须标注：L3–L6；E2（改范围自动授权落操作人、admin 自锁 / 历史模板孤儿）登技术债，不阻上调。
