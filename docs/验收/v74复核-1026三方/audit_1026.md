### 若上调到「正偏离/无偏离」，反驳者最可能打回的三点

1. **「检验单/检查单」歧义 → 检查报告单零打印、检验报告单入口未提交。** 参数字面没写"申请"。若反驳者读作报告单：RIS 检查报告没有任何打印按钮、`PrintView` 无该 type（#3b，硬缺）；检验报告单在 HEAD 上"后端有、前端零入口"，两处入口只在工作区（`git status` 两个 M 文件），反驳者按 HEAD 走演示路径会走不通（#2b）。对策：上调说明必须写明"检验申请单/检查申请单"，且现说明里"已提供检验报告单打印能力"一句在 HEAD 上站不住——要么先提交这两处入口，要么删掉该句。

2. **纸上内容与医嘱录入不一致（#15）。** 医生在开单时填的检查目的/临床摘要/标本类型/采样部位/注意事项/加急，后端返回了、打印页一个都不印，检查申请单「检查目的 / 临床要求」仍是空栏。CHANGELOG v44 `:1127` 写"有值印值"是**失实**，v74 已记技术债。反驳者只要开一条填了检查目的的检查医嘱再打检查申请单即可复现。这是"功能有但打出来的单子不对"，比"没功能"更容易被判打回。

3. **打印功能的"厚度"不够：无留痕、无单张、无批量、条码只留位。** 反驳者会拿收费票据做对照——票据有「票据补打」检索、已打次数、`fin_print_log` 留痕（`ChargeView.vue:99-121`），而五种临床单据被**刻意**排除在留痕表外（`PrintReportController.java:91-99` 决策注释）；一次就诊多张处方只能整批打、不能选一张（`groupNo` 仅 API 层）；条码位不出条码图形；导诊单诊室为「—」。参数字面虽只说"拥有打印功能"，但★条款上调到「无偏离」时，反驳者可主张"处方笺无留痕不满足处方管理办法留存追溯要求"。对策：上调说明如实写"条码位/留痕/单张打印属实施期配置或后续增强"，不写成"完备打印中心"。
