# v162 授权候选会话与错误对象授权复核

模板授权候选绑定当前模板、对话框会话与候选类型。切换类型立即清空选择，加载完成前禁止授予；旧候选不再把所见科室的同号 ID 按个人提交。授权列表及授予、撤销回包也只更新原会话，旧回包不能清除新选择或提前解除新提交的等待状态。

## 修复与回归

授权候选请求使用模板 ID、对话框会话、请求代次与类型共同确认归属，重复切换到同一类型也不会接纳第一轮回包。候选成功加载后才允许选择当前列表成员；授予前再次校验可维护对象及候选来源。授权列表另有请求代次，关闭、换模板与组件卸载使旧上下文失效。

授予和撤销在发请求前固定模板路径和提交对象；等待期间禁止重复操作。晚到成功与 finally 只能更新所属会话，新会话的选择、授权表和等待状态不会被旧操作改写。API 动词、路径、请求键与后端权限判定均沿用；原授权列表读取及授予、撤销失败继续向调用方 reject，客户端错误提示保持原样。普通模板 load/save 的其他竞态未在本轮修改。

新增 21 项完整 Vue SFC 真实挂载测试，执行实际模板绑定、watch 和生命周期，仅将 Element 控件与网络传输作为测试替身，不引入测试依赖。相同最终测试 SHA 在原生产 Vue 中得到 18 项产品断言失败、3 项控制通过；其中实际捕获了 USER 与科室重号 ID 的错误 POST。旧 finally 项在旧版更早暴露原会话 busy 阻挡新会话提交，不能称为旧版已单独执行到最后的 finally 断言；固定后该最终边界实际通过。

首轮完整前端的 41 项失败集中于两组既有 VM 兼容测试：原夹具直接设置 ref，未建立新的会话与候选加载过程，且把新会话打开时已清除的旧授权表当作保留目标；初版生产修复还多加了三个 catch，改变原 reject 语义。已撤回这三个 catch，保留原拒绝契约，再把夹具改走真实 openGrants、类型 watch 与候选加载；读拒绝断言改为核对请求发出后的当前会话，同时保留未存正文、请求契约、单错误、无假成功、无自动重试及令牌规则。原首跑报告保留，没有用测试期待变化掩盖产品授权错误。第二轮全部行为测试已绿但新测试清理队列发生循环类型引用；修正测试类型后，用相同最终 SHA 重做旧版与修复版对照，第三轮完整前端及类型、构建全部通过。
