# v91复核：用血与手术岗位及对象权限

状态：2026-10-18本地定版v1.8.10，基线v1.8.9，尚未推送。

## 修复边界

用血申请限ADMIN/DOCTOR_OUTP，普通医生需当前主管或未归属且可解析真实用户；审批和发血限ADMIN，输血记录限ADMIN/NURSE。未建立独立血库专岗，不新增TECHNICIAN用血入口。用血列表按当前主管过滤普通医生，ADMIN/NURSE保留横向护理执行；在100条限制前SQL过滤。

手术申请、完成手术/麻醉终结记录、取消，以及手术级别/ASA/切口等级/手术类别/非计划再次手术等医师字段，限ADMIN/DOCTOR_OUTP并按当前住院主管授权。历史surgeon_id或同患者其他住院不扩权。手术时间点、roomNo、术中管路/输血/事件保持ADMIN/NURSE/TECHNICIAN既有协作；普通医生仍按主管。麻醉记录与PACU判定保持原ADMIN/DOCTOR_OUTP/TECHNICIAN岗位，未给护士新增麻醉记录权限。

列表、手术间排程、详情、术中聚合及明细、麻醉记录均检查读取对象；子记录写入从数据库真实所属手术授权，不信任请求surgeryId。住院→手术→子记录统一锁顺序，持锁至写入结束；用血申请和医师完成等待主管移交后按最新归属核验。HTTP角色门槛全部保留或收紧，无登录上下文的可信内部调用沿用既有服务兼容约定。新增V178，仅补既有菜单40/45及父目录18的角色绑定；无新菜单ID、错误码、配置或返回键。医生获手术/用血入口，护理/医技获手术执行入口，医技不获用血菜单；拒绝1005/9018沿用，不存在与状态码、空明细列表等原契约保留。

前端用血隐藏越岗申请/审批/发血/输血按钮；手术隐藏非医师申请/完成/取消，医师字段只读且不由护理/医技请求回传。手术列表、排程、术中和麻醉读取先清空旧数据，抑制较早请求覆盖；麻醉两次请求均成功后才展示，避免混合两个病例。

## 仍开边界

血库专岗/审批额度与申请审批人员分离、麻醉/手术团队及病区分配仍缺独立业务模型，现有护理/医技横向授权不能称为团队隔离。质控报表、专病、护理文书、账号撤权并发、历史不合格主管及门诊单归属同意书对象权限继续待偿。开发环境Mock签名/集成与虚构患者验证不替代生产血库、CA或临床制度验收；不代签负责人。
