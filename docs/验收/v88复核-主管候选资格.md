# v88 复核：入院与主管移交候选资格

状态：开发验证中，未定版、未发布、未推送。基线 v1.8.6。

## 问题与修复

既有主管字典只列启用的 DOCTOR_OUTP/ADMIN，但入院直接接受 doctorId，主管变更只检查账号启用。启用的护士、收费员或无岗位账号可成为主管，造成岗位与病案归属脱节。

两个写入口统一使用 InpatientWriteAccess.assertEligibleAttending，在事务内查询真实用户启用状态和数据库角色。管理员候选、医生候选、多岗位中具有医生岗位者继续可选。入院不传主管仍允许；主管移交不允许清空。已有医生对象归属、ADMIN/NURSE 入院岗位门槛不变。

入院校验先于建档、占床、押金写入；移交先按现有住院行锁检查操作人归属，再校验目标，最后更新。不存在住院仍 9003，非法目标复用 4884，无迁移、配置或菜单变动。

## 边界与剩余优先级

1. 高：入院登记岗位及普通医生能否替他人建档的业务口径；护理病区分配模型仍未建立，本轮不擅自改变既有流程。
2. 高：住院检索、医嘱搜索、费用、体征、完整性预览及其他打印读取的对象范围继续审计。
3. 中：DiagnosisController.add 归属检查与写入之间的主管移交竞态，保留 QUALITY 编码职责。
4. 中：账号停用/角色撤销与指派事务的并发序列化，以及已存在的不合格主管存量审计。当前校验每次写入时重新查询资格，未宣称与账号管理互斥提交。
5. 后续：医生菜单与同步按钮可见性、未归属历史病例政策、结构化侧车。

本轮不承诺所有住院权限问题清零；不代签投标或负责人签认。
