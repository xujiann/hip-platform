## 七、新发现 / 缺陷（按镜头分，给反驳者当靶子）

**数据口径镜头**
- **D3【992/1019，中，阻断上调】EXAM 不过滤报告状态**：`EmrRefController.java:429-439` 的 SQL 对 `ris_exam` 没有任何 status 条件，REGISTERED（没出报告）和 REPORTED（写了报告未审核）都会进入「检查报告」，并且可以插入法定病历。同仓其它地方对「检查报告」的口径都是 `status='VERIFIED'`：患者端 `PortalController.java:208-211`、检查互认 `MedTechController.java:265`、报告分享 `ReportShareController.java:32`。同一个控制器里 MICRO 只取已发布、PATH 只取已签发，唯独 EXAM 不限。实测 5 条没出报告的行以「腹部彩超」的样子出现在【检查报告】段落里。连带问题：病理医嘱也是 EXAM 类型，会被 RIS 队列的 GET 请求自动登记成 `ris_exam`（REGISTERED，开发库有 36 条），在 EXAM 页签里以光秃秃的「组织病理学检查(活检)」出现，和 PATH 页签里的真报告重复。修法（S）：在 `:436` 加 `and e.status = 'VERIFIED'`（`outp_order_report` 那一支另定口径），再补一条「未审核不可引用」的用例。
- **D4【994，中，强烈建议上调前修】同一页留痕用了两个时钟**：正文版本 `saved_at` 由应用时钟显式写入（`EmrVersionService.java:432`，取自 `nowMicros()` `:252-253`）；诊断版本 `changed_at` 不传值，用的是库默认的 `now()`（`DiagnosisVersionService.java:100-104`，`V170__outp_diagnosis_version.sql:45`）。**实测**（挂号 1064 / 病历 #100）：诊断 v1/v2/v3 = 11:34:31.62 / .72 / .81；正文 v1/v2 = 11:34:33.42 / .57。**第 3 次保存产生的诊断版本，时间早于第 1 次保存产生的正文版本**。版本页两块都格式化到秒（`types.ts:162-166`），屏上可以直接看到「诊断 11:34:31 已删光，正文 11:34:33 才初版」。本机库时钟落后约 2–3 秒，这就是交接单「应用时钟与数据库时钟混用」那一项仍开着的问题，第一次出现在法定留痕页上。修法（S，一行）：两侧统一取同一个时钟，诊断 insert 显式传 `changed_at`，或正文改用库默认值。
- **D6【994，低】诊断留痕没有照顾 gate 的 block 档，也没有计数**：`DiagnosisVersionService.java:109-116` 无论哪个档位都只吞掉异常、记 ERROR。block 档下正文留痕失败会让保存失败（5705），诊断留痕失败却静默放行；`settings()` 的失败计数也不包含诊断。类注释「开关复用 emr.version.gate」只兑现了 off 档。
- **D8【994，低】版本列表不校验主记录是否存在**：`OUTP/999999` 返回 code 0 和空态提示「本份病历暂无版本记录…」，而不是 5707（`EmrVersionService.java:645-662`）。
