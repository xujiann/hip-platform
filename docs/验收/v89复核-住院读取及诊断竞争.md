# v89 复核：住院读取范围与诊断写入竞争

状态：开发验证中，未定版、未推送。基线 v1.8.7。

## 修复范围

普通医生按当前住院主管或未指定主管读取，必须解析到真实用户。默认在院列表、指定医生/其他筛选、医嘱搜索、待执行临时与长期执行行均不能扩权。医嘱搜索在 200 条上限前 SQL 过滤；床位空占状态保持，越权床位省略患者姓名。

补齐每日费用、费用清单打印、账户、转科留痕、中间结算、病历完整性预检、体征、体温单、其他诊断列表的对象校验。ADMIN/NURSE 保留既有临床范围；CASHIER 仅在原有费用打印、账户、中间结算入口横向读取；QUALITY 在诊断编录入口横向读写，未扩大到其他临床读取。护理病区模型尚未建立。

诊断写入进入独立服务事务，先与主管移交共用住院行锁，再按实时主管核验，持锁至插入结束。重复 ICD 通过唯一键 ON CONFLICT 不写入，保留 9015，并避免捕获异常后的 PostgreSQL aborted 事务。未知普通医生对未指定主管同样拒绝。可信非 HTTP 无安全上下文调用沿用既有写服务规则；HTTP 角色门槛不变。

诊断删除仍限 ADMIN/QUALITY，服务层同样限制岗位；先查询所属住院并锁父行，再删除子行，避免与新增锁顺序相反。不存在诊断仍9016。

无新增迁移、错误码、菜单或配置；读取拒绝1005、写入拒绝9018、住院不存在9003、体温单不存在4820、ICD必填9014及重复9015沿用。响应字段结构保持，集合行集按新权限收窄。
