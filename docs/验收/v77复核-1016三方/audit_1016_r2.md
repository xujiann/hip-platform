### Q2 「流向」的实现是否配得上「根据流向自动获取执行科室」

- **规则键**：`charge_item_id`（必须 category=LAB 项目，否则 5912）、`specimen_type`（落规范化值：去首尾与内部空白、大写，`LabRouteService.java:125-129`）、`order_dept_id`（= 挂号科室 `outp_registration.dept_id`，**不是开单医生所在科室**，`DoctorStationService.java:836`）；三键全可空 = 通配；目标 `exec_dept_id` 必填且须启用（5911）。
- **匹配顺序**（`LabRouteService.java:79-91`）：候选 = 启用且 `item_category='LAB'` 且「所有非空键全相等」；排序 = 具体度分 **项目 4 + 标本 2 + 开单科室 1** 降序 → `priority` 升序 → `id` 升序；取首条。**这是加权而非计数**：只配项目的规则（分 4，1 个条件）压过配了标本+开单科室的规则（分 3，2 个条件）→ 说明「条件越具体越优先」有歧义（N5）。医嘱标本为空时带标本键的规则不匹配（`null = x` 为 unknown）。
- **无命中回落**：`md_charge_item.exec_dept_id`（source=ITEM，不校验该科室是否启用，`:114-122`）→ 仍空则 NONE（null，纸上「—」）。
- **开关**：`sys_config.lab.route.enabled`（V174 种 `1`），非 `"1"` 直接回落字典（`:74-76`）。**全仓前端零处调用 `PUT /api/config/{key}`，`sys_menu` 无配置页**（实测 grep + 库查），只能管理员调接口或直改库（ConfigReader 缓存 30 秒）。规则页只写「总开关为系统配置 lab.route.enabled」（`LabRouteRuleView.vue:20`），**不显示开关当前状态，也不说在哪改**；开关关闭时试算返回 ITEM，页面文案是「无规则命中，按收费项目字典 →…」（`:213`）——实际是「未查规则」，**文案与事实不符**（N6）。
- **停用科室**：规则指向的科室停用 → 该候选跳过、warn 日志、取下一候选（`:93-97`）；历史快照仍指向停用科室，打印/队列照 name 显示（交接单已记）。
- **快照语义**：落值即快照，改/停/删规则不回改（`V77LabRouteTest#createOrdersWritesSnapshotForLabOnlyAndEchoesDeptName:374-379`；E2E [4] 段）。`outp_order.exec_dept_id` 无外键（刻意）。
- **异常**：`resolve` 捕获一切异常回落字典、不打断开单（`:102-111`）。
- **标本自由文本实测**（开发库，规则「审计A：血常规+血清→影像科」「审计B：内科门诊开单→检验科（通配）」「审计C：全血+内科门诊→影像科」；`GET /masterdata/lab-route-rules/resolve?chargeItemId=1&orderDeptId=1&specimenType=…`）：

| ` 血 清 ` | 影像科 | RULE 审计A（空白被规范化） |

## 六、审计意见与须标注项

**审计意见：建议上调（部分响应 → 正偏离/无偏离）**，前提是说明按下文逐句加限定，并同批订正 1026 说明（N9）。

**反驳者最可能打回的三点（按镜头）**

1. **子要求拆解（N1/N2）**：「自动获取病情摘要」落地为一段**可改的预填文本**，而申请单另有一行**打印时现查的病史摘要**——两份摘要并存，哪一份才是参数要的「自动获取」？且先加行后写病历则预填为空。对策：说明如实写两行各自时点；预填的那一行才是「检验申请自动获取」的载体（随申请单保存、医生可改、可被医技看到），病史摘要是单据版式沿用项。
2. **演示可行性（N4/N7）**：演示库上分流演不出来（单一检验科室、技师无科室），执行科室在医生站只闪一次 toast。对策：说明写明实施期配置前置；培训脚本补第 0 步（另开仓库改动）。

本平台门诊医生站开具检验申请时可填写标本类型与采样部位，随申请单保存、印出并在检验科待采样与标本流转列表显示；检验、检查医嘱录入行即时展示病历区当前录入的诊断名称，并在加入行时按本次门诊病历的主诉与现病史自动预填临床摘要（医生可改，超长截断提示），临床摘要随申请单保存并印出，申请单另印本次就诊已保存的临床诊断与打印时取自病历的病史摘要。执行科室按「检验流向规则」在开单时自动确定并随医嘱保存：规则以检验项目、标本类型、开单科室（即挂号科室）三个条件匹配，按项目、标本类型、开单科室的先后权重取最具体者，再按优先级；无规则命中时按收费项目字典配置的执行科室带出；规则由系统管理员或医技技师角色在基础数据下维护，可停用、可试算；开单成功提示中显示本批检验申请的执行科室，检验申请单与导诊单逐行印出，检验科待采样与标本流转队列可按执行科室筛选（默认登录人所在科室）。说明：临床摘要预填后修改病历不自动同步；执行科室在已开医嘱列表不显示；规则按医生实际填写的标本类型匹配，仅与规则配置值完全相同（忽略大小写与空白）时命中，标本类型为自由文本、未字典化；流向规则仅对门诊检验类医嘱生效，检查、治疗类按收费项目字典带出，住院检验申请暂无执行科室分流；执行科室在开单时落值，此后修改规则不改已开出的申请；流向规则总开关由系统管理员通过配置接口设置，默认开启；执行科室与检验技师所属科室由院方在实施期配置。
