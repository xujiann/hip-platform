## 一、我的独立拆解 / 与审计者差异

参数原文：「拥有检验申请自动获取病情摘要、诊断，能填写标本类型、采样部位等信息，并根据流向自动获取执行科室。」
语法：主语是「检验申请」（申请这份记录/这个动作），三个并列谓语：**自动获取**[病情摘要、诊断]；**能填写**[标本类型、采样部位 + 等信息]；**根据流向自动获取**[执行科室]。「自动获取」出现两次，主语都是「检验申请」——字面是「申请**本身**带有/取得」，不是「医生看得到」；但「申请」是医生在开单界面创建的，若创建那一刻看不到带出了什么，就只能算"申请单这份文件最终带了"，这正是第一轮打回点 R1 的由来，所以两个位置都要看。

### 口径 1：「等信息」是否蕴含采样时间 / 采样人 / 标本量 / 容器

- 字面：按本表先例「等」不增义务（D1）。
- 事实：检验申请单版式留了手填栏「标本要求（采集容器 / 采集时间 / 送检要求）」与签名栏「采样人 / 时间」（`PrintView.vue:220-226`）；采样时间在 LIS 采样打码时落 `lis_sample.collected_at`（库列核过：`collected_at/received_at/published_at/verifier_id/substitute/substitute_name`，**无采样人列**，替检人另记）。即：采样时间由采样环节自动记，采样人只在替检时记名，容器/标本量无字段。
- 判定：不计入 1016；但若评委追问「等信息」，答法是「采样时间在检验科采样打码时记录，容器与送检要求在申请单留手填栏」。说明里可不写。

### 口径 2：「自动获取」的语义——"开单时带出到申请"还是"申请单上有"

- 第一轮维持的理由就是"只在打印页有"。v77 后两处都有：开单界面（行内标签 + 预填框，`DoctorStationView.vue:365-378`）与申请单（`PrintView.vue:164/202/206`）。
- 但要诚实：**界面上的"自动获取"是预填到一个可改的输入框**，医生提交的是框里的值，不是系统独立取的值。这是检验申请的通常做法（摘要本来就该医生可改），不是打折。申请单上另一行「病史摘要」才是"系统独立取"的那份，打印时现查病历。两份并存（审计者 N1），我核了取数：`PrintReportController.java:285-289` 查 `outp_emr`，`print-format.ts:96-100` 以「；」拼主诉与现病史；`:353 SHEET_LEVEL_COLS` 的 `clinical_summary` 取组内首个非空。默认路径下两行文字相同只差前缀。
- 判定：A1 做实。「哪一行才是参数要的」——我与审计者一致：预填并保存的「临床摘要」是载体（随申请保存、医生可改、医技在 RIS 列表能看；LIS 两队列**不显示**临床摘要，只显示标本/部位/加急/备注——`MedTechController.java:99-100` 列清单无 `clinical_summary`，这点审计者没提，属 1013/1014 范畴不计 1016）。「病史摘要」是版式沿用项，1026 说明已写明「病史摘要于打印时取本次门诊病历」。1016 说明须把两行都写出来，否则评委对着纸问"为什么印两遍"没有答案。

### 口径 3：「流向」在检验业务里的通常含义 vs 三键规则

检验业内"标本流向/分流"通常按：①标本类型（微生物/血清/全血分室）②项目（外送项目→外送）③送检科室（急诊/病区→急诊检验室）④急缓（加急标本→急诊室）⑤时段/值班（夜间→急诊室）⑥患者类型（门诊/住院）。
v77 三键覆盖 ①②③；④ `outp_order.urgent` 有列但不是规则键（`LabRouteRule` 实体与 `resolve` SQL 零 `urgent` 引用）；⑤ 无；⑥ 住院 `inp_order` 无任何 dept 列（库查 `information_schema.columns like '%dept%'` 为空），住院检验**没有执行科室概念**，审计者 N10 属实。「外送」可用一个 MEDTECH 科室建模（`exec_dept_id` 只要求 `sys_dept` 启用），不须另造概念。
判定：参数只写「根据流向」未定义维度，三键 + 优先级 + 字典回落是**合格的**流向配置；A6 做实，但说明不得出现「动态」「智能」「按加急/时段」字样。CHANGELOG 标题「动态确定执行科室」、规划节「动态路由」是内部文档，不改；CSV 现文没有「动态」，守住。
