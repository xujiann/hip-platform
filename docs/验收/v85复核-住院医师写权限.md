# v85 住院医师写权限复核（2026-10-16）

基线 v1.8.3。原主管设置接口允许任意医生/护士改任意住院记录的 doctor_id，能绕过依赖该列的病历创建、CDR 和诊断归属检查。住院开嘱、作废、停嘱、主出院诊断同样只有宽角色门槛。

本轮五个 HTTP 入口限 ADMIN/DOCTOR_OUTP，普通医生须为当前主管或源记录未登记主管；拒绝复用 9018，护士继续执行临时医嘱、长期执行行和录入体征。原主管/管理员可移交主管，移交后旧主管不能继续决策写入，新主管可接手。主管目标账户沿用原启用校验，角色资格未扩面处理。

服务事务内通过 InpatientWriteAccess 锁定住院行并核验实时归属，授权不依赖客户端传入的医生 ID；主管设置与三类医嘱决策、主出院诊断共用该行锁。可信非 HTTP 无登录态服务调用沿用既有模式，HTTP 入口全部有角色鉴权；真实 HTTP 普通医生必须能解析到用户 ID。控制器不包外层写事务，不吞掉业务异常后再触发提交异常。

## 剩余优先级

- **高：其他住院临床动作**。`InpatientController` 的入院、转床、出院/结算流程仍需逐入口核定操作对象范围；目前存在医生/护士类级权限，不能据此宣称受主管或病区约束。须保留合法护理/收费工作流，不能只删角色。
- **高：其他住院读取**。`InpEmrController.records/rounds/amendments`、住院工作区和出院小结仍需对象校验；补正历史尤其未核对路径 admissionId 与 recordId 的父子对应。护理按病区读取的模型尚未建立，本轮不静默限流。
- **中：既有其他诊断入口的归属竞态**。`DiagnosisController.add` 已有 9018 对象检查，但未与主管移交共用行锁；编码组 QUALITY 的合法横向写入须保留，独立补并发回归后处理。
- **中：EMPI 与其他打印/调阅入口**尚未全库审计，不能从 CDR 修复推导全局病历隐私完成。
- **后续：主管候选角色资格、患者360同步按钮角色显示、未归属历史号规则、住院结构化侧车同步**。候选仍按启用账号校验；这些边界未在本轮改变。

无新错误码、迁移、菜单和配置键；负责人签认与投标结论不变。
