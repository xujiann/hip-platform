## 保留项（须标注，均不构成参数字面走不通）

- **R1（演示前置）**：门诊「套用正文」依赖院内至少一张对 doctor01 可见的门诊模板；已由脚本种一张，但只有"全新库已跑 `bootstrap-demo.py`"才成立；偏离表说明里"门诊医生站模板栏在院内已有可用的门诊病历模板后显示"这句限定必须保留（审计建议稿已含）。
- **R2（演示顺序）**：`docs/培训脚本.md` doctor01 节第 5 步先签名、第 7 步才套模板，同一份病历按此顺序走会遇到按钮禁用。讲师须在签名前演示，或另挂一名患者；建议培训脚本补一句。
- **R3（DRG 补录页）**：住院ID 需敲内部数字 id，页面无处展示；"重新入组看细分组变化"只对已出院病例有效，脚本不造。不影响"住院其他诊断已字典化"这一字面，但按培训脚本第 153 行"补录后重新入组看细分组变化"在脚本数据上演示不出来。出院结算页是更稳的住院诊断演示入口（点患者行即可）。
- **R4（CSV）**：(a) 示例 CSV 两行均已在库，导入只"更新"；(b) 评委若用 Excel 另存的 CSV（默认 ANSI/GBK），`file.text()` 按 UTF-8 解码出 U+FFFD，后端只校验名称非空与长度，**乱码名称会被成功导入**——`IcdDictController` 类注释声称此类错误"整批拒绝"，但实际无 U+FFFD 检测；演示文件须 UTF-8。
- **R5（口径细节）**：9105 在屏上走前端预拦警告，评委看不到该码；出院诊断空关键字下拉首屏 20 条按 code 序，非全部；pharm01/tech01 敲 URL 可只读进入诊断字典页（读开放、写限 ADMIN，与"维护限系统管理员"说明一致）。

## 结论 + 一句理由

**不推翻但须标注的保留项**（R1–R5，其中 R1、R2 必须落进说明或演示前置清单）。理由：参数字面要求的每一条演示路径——诊断字典浏览/维护/CSV、出院登记与 DRG 补录的字典检索、门诊模板栏→套用正文→覆盖确认→五段回填→保存、停用后医生站搜不到——在代码与库态上都能一步步走通，且 HEAD 补的演示模板在 doctor01 视角下实测可见、拆段与覆盖确认实测正确；走不通或看到与说的不一致的地方（未跑脚本的零模板库、先签名后套用、DRG 数字 id 与重新入组、GBK CSV）都是演示前置与顺序问题，未把参数字面要求的功能变成不存在。
