# HIP 停机应急预案（SOP）

> 上线前审查列此为必补文档：系统真宕机时夜班无所适从是最危险的场景。
> 本预案给一线一条"系统不可用时先看病、恢复后补录"的可照做流程。
> 面向院方信息科与各科室值班长。

## 一、判定与上报（谁先发现，谁先做三件事）

1. **确认范围**：是本机断网（换台电脑能否打开）、还是全院不可用（问其他科室）。
2. **立即电话**信息科值班（非工单——系统都打不开了，工单也发不出）。
3. **启动纸质降级**：不要等系统恢复，按下方流程先保障病人。

信息科接报后：查 `docker compose -f deploy/docker-compose.full.yml logs server` 与
`... logs postgres`；健康检查 `curl http://localhost:8080/actuator/health`；
主备已搭的院区按 `docs/彩排与升级演练记录.md §九` 判断是否需故障切换。

## 二、各岗位纸质降级流程

| 岗位 | 系统不可用时 | 恢复后补录 |
|---|---|---|
| **挂号** | 纸质登记：姓名/性别/年龄/联系方式/科室，发纸质就诊序号 | 按纸质记录补建档补挂号，就诊时间填实际时间 |
| **门诊医生** | 纸质处方笺 + 纸质病历（模板打印备用空白页放诊室） | 补录病历与医嘱，签名时注明"XX 时段停机补录" |
| **收费** | **先看病后补费**：登记患者与金额白条，不收现金找零凭据先手写 | 恢复后按白条补收费，日结时单独核对停机时段 |
| **药房** | 凭纸质处方发药，手工记录扣减的药品与批号 | 补录发药，人工核对库存与手工记录差异 |
| **护士/住院** | 纸质医嘱执行单、纸质体征记录 | 补录执行与体征，时间填实际 |
| **检验/检查** | 手工登记标本与申请，出纸质报告 | 补录申请与结果，危急值电话已口头通知的注明 |

**纸质单据统一保管**：每个窗口指定一人收齐当班纸质记录，恢复后交回补录，
补录完成前不得销毁——这是停机时段唯一的原始凭据。

## 三、恢复后的对账（信息科 + 各科室）

1. **收费轧账**：停机时段的白条金额合计 vs 补录后系统金额合计，逐笔核对。
2. **库存核对**：药房手工扣减记录 vs 系统补录后库存变化，差异当日查清。
3. **就诊连续性**：抽查停机时段建档/挂号/病历是否补齐，有无遗漏患者。
4. **危急值回溯**：停机时段检验危急值是否都已口头通知并补录留痕。

## 四、预防与准备（上线前落实）

- **纸质模板常备**：挂号登记表、处方笺、病历空白页、医嘱执行单、体征记录单，
  每个窗口/诊室/护士站备足一周量，锁抽屉定位放置。
- **值班长备用可重置账号**：夜间员工忘记密码时，系统只支持自助改密（需旧密码）
  与管理员重置——夜班无管理员在场时会卡住。**每个夜班值班长持一个有用户管理权限的
  账号**（或信息科 24 小时电话可远程重置），避免"密码忘了整夜进不去"。
- **主备切换演练**：搭了主备的院区，信息科按 §九 每季度演练一次故障切换，
  确保真出事时切得动。
- **备份可恢复**：每月抽一次备份到校验库跑通业务回归（判据见部署手册），
  确认"备份能真恢复"而不只是"文件在"。

## 五、忘记密码的处置（明确到人）

平台**当前不支持无旧密码的自助找回**（有意——短信找回需短信通道且是新攻击面）。
处置路径：

- 白班：本人找管理员，管理员经用户管理重置口令（重置后首登强制改密）。
- 夜班：值班长用备用账号重置，或电话信息科远程重置。
- **切勿**为图方便把多人口令设成同一个或写在便签上——等保与安全底线。
