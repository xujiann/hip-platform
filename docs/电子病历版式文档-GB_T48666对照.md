# 电子病历版式文档建设对照

本项目以 GB/T 48666—2026《电子病历版式文档技术要求》作为电子病历版式文档建设依据。标准发布日期为 2026-09-28，实施日期为 2027-04-01。日期采用标准封面及国家标准公开记录。[国家标准公开记录](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=CDD0F56BBBDDF7B69D01AC4DCFAB0C76)

本次核对使用用户提供的完整 19 页 PDF。原件 SHA-256 为 `3d2f59ea5f7d03c72d2f4257e5bf3e0f110ab87214792ea526eea31f7a979e7a`。原文件保留在用户指定位置，分析和开发产物保存在 Projects 内。

## 首批实现

v166 的代码范围是住院历史病历版本的未签署 OFD 预览。版本详情页中的操作绑定所选版本，源数据来自现有 `emr_version`。生成前校验原始 UTF-8 内容的 SHA-256、Java 字符长度及已支持的住院字段结构。没有历史版本时，由原版本页面显示实际情况。

每个预览有独立文档标识、OFD-H 类型和医疗敏感属性。可读页面和 `source-metadata.json` 附件共享同一来源。附件含头信息、文档属性、来源版本、原始快照、当前主索引上下文、生成责任者和待处理项。患者及显示姓名来自生成时的当前主索引，标注采集时点；原版本保存时间和保存人标识沿用原记录。

生成器采用 OFDRW，字体采用带 OFL 许可和来源记录的 Noto Sans CJK SC。首批输出显示未签署预览状态。临床正文中的签名字段、SUBMIT 保存来源及数据库归档标记各自沿用原业务语义。

当前预览会明确拒绝补充平面字符，防止输出缺字框；原始历史快照保留完整。GB 18030 全字符的版面覆盖列为后续验收项。附件内部使用 Attach_0.json，阅读器显示名称为 source-metadata.json。

## 生成件留存（v168 / v1.8.87）

住院历史版本新增独立生成件表，保存完整 OFD 字节、来源版本与摘要、原患者/住院关联、生成责任者和采集时间。每次主动生成追加文档标识，取回时返回原文件并校验长度与 SHA-256。列表最多显示当前来源下最近 50 件。渲染后及写入后复核当前权限，列表和文件取回也在返回前复核；末次 SQL 快照后的变化不追撤。原患者或住院关联已变化的旧件不能取回，也不在列表中展示。

数据库触发器阻止普通 UPDATE/DELETE，完整文件随 PostgreSQL 备份保存；这不是防数据库所有者篡改的证明。当前仍为 UNSIGNED_PREVIEW，尚未形成签署、补注、正式归档与患者文档集的完整版本链。

v169 增加同一住院历史版本留存件翻页。每页最多 50 件，游标仅在当前授权、原患者及住院关联和来源指纹均匹配时有效。界面可查阅更早生成件，且各页均可取回原文件。

## 后续批次

1. 版式文档版本与归集。完成留存件验收后，继续支持签署版本、补注与患者文档集，设计既有资料的来源标识、容量和长期保管策略。
2. 商密签署与验证。接入真实证书、签章服务和可信时间戳，核对保护范围，支持脱离业务系统的验证及证书状态检查。
3. 多来源转换与附件。覆盖门诊、医技、护理、扫描件、DICOM 关联与内外附件，配置大文件处理策略。
4. 阅读与标准核验。提供版面还原、元数据与待处理项展示、签章验证、权限控制和外部附件定位，并开展第三方验证。

旧版模板创建末次权限复核继续保留在开发待办。病案复印预览的对象竞态、已出件内容快照与既有归档事件的重复写入，也需按文档版本和患者一致性要求分批修复。

## 验收约束

首批须核对真实容器、单文档结构、可读版面、嵌入字体、原始机读快照、完整性错误拒绝、当前权限和归属拒绝、生成期间撤权、前端旧回包以及真实下载。正式生效归档还需完成签章、独立验签、长期保存与第三方验证等后续验收。
