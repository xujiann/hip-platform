# 多医院部署操作指南（v1.0，2026-08-06）

> 读者：实施工程师。前置阅读：docs/产品化方案.md（四层模型）、docs/部署手册.md（单机细节）。
> 形态铁律：**一院一实例一库**，全部医院使用**同一个标准发布产物**；医院差异只存在于
> 配置（L2）、适配器实现（L3）、impl 定制模块（L4）。标准核心永不分叉。

## 一、部署形态与资源要求

每院独立部署（院内网），一台应用服务器即可起步：

| 组件 | 要求 | 端口 |
|---|---|---|
| 应用（server jar） | Java 21（Temurin） | 8080 |
| 数据库 | PostgreSQL 16，独立库 | 5432 |
| 前端 | nginx 托管 dist + 反代 /api，TLS 终止 | 80/443 |
| MLLP 监听（接检验设备） | 可选，`hip.integration.mllp-enabled` | 2575 |
| ai-service | 可选（缺席自动降级） | 8100 |

两种装机方式二选一：`deploy/docker-compose.full.yml` 全栈容器，或裸机（jar + nginx + 系统 PostgreSQL）。

## 二、单院部署七步（每家医院重复执行）

### 第 1 步 · 装机
1. 生成并设置 JWT 密钥（**必做**）：环境变量 `HIP_JWT_SECRET`（≥32 位随机串，`openssl rand -base64 48`）
2. 建空库（owner 授给应用账号），启动应用——Flyway 自动建 V1-V43 全部结构与 A/B 类种子
3. nginx 挂前端 dist、反代 `/api`、配置 TLS

### 第 2 步 · 初始化（init-hospital）
1. 复制 `tools/init-templates/hospital.example.json`，按院填写：
   - `hospital.name` 院名（前端/打印/患者端全联动）
   - `modules`：未采购模块置 false（DRG/CDSS/医保/用血/人事/手麻——菜单与 API 双关闭）
   - `depts`：门诊科室 + 病区（`type: NURSING` 带 `beds` 数自动建床）
   - `accounts`：业务账号与角色
   - `adminNewPassword`：**必填**，工具末步强制更换 admin 口令并验证
2. 执行：`python tools/init-hospital.py <院配置>.json --base http://<host>:8080`（幂等可重复）
3. **该院配置 JSON 存入实施资料库**（每院一份，是重装与审计的依据）

### 第 3 步 · 字典与数据迁移
| 数据 | 途径 | 模板 |
|---|---|---|
| 药品目录 | init 配置 `drugsCsv` 或 `POST /api/masterdata/drugs/import` | tools/init-templates/drugs.example.csv |
| 收费项目 | 同上 charge-items | charge-items.example.csv |
| 医保对照 | `POST /api/insurance/catalog/import`（管理页有对照率统计） | tools/migrate-templates/yb-catalog.csv |
| 存量患者 | `python tools/import-patients.py`（同证件号幂等） | migrate-templates/patients.csv |
| DRG 目录 | 官方目录整表替换 drg_group_def/drg_cc_list 后 regroup-all | — |

### 第 4 步 · 接口适配（各省各院差异所在）
先填**接口现状调研表**（医保/LIS 设备/PACS/CA/支付商与联系人），再按 SPI 对照实施：

| 差异点 | 接入点 | 约定 |
|---|---|---|
| 医保 | InsuranceAdapter（换省 SDK 实现 Bean） | **ADR-0002**（结算号回传/留痕关键字/失败语义） |
| 聚合支付 | PayAdapter | 同构留痕 |
| CA 签名 | SignatureAdapter | 病历签名冻结语义不变 |
| 检验设备 | MLLP 2575 / HTTP ORU + int_adapter 路由 | HL7 V2 ORU^R01 |
| AI | ai-service HTTP（可缺席） | 平台侧优雅降级 |

未到位的适配器保持 Mock——业务闭环完整可用，对接后无缝切换。
同省同商的适配器实现包**跨院复用**，放实施仓库统一维护。

### 第 5 步 · 真定制（如有）
按 **ADR-0003**：复制 `impl/template-hospital` 为 `impl/<hospital>`，V10000+ 迁移段、
`impl_` 表前缀、`/api/impl/**` 路由。实施仓库根 pom 挂载；标准仓库不动。

### 第 6 步 · 制度化运行
- 备份：`tools\schedule-backup.ps1` 注册每日任务（02:30），按 `db-restore.ps1` 做一次恢复演练留档
- 告警：运维中心健康阈值核对（磁盘/备份时效/慢接口）
- 医保：每日自动对账默认开启（01:30，差异自动开故障工单）

### 第 7 步 · 培训与试运行
- 按 docs/培训脚本.md 跑 8 角色 + 患者端真人培训
- 验证：`python tools/e2e-outpatient.py`（指向该院测试库演练）
- 试运行问题一律进运维中心故障工单台账，按第四节「分层归位」处置

## 三、多院并行管理（车队管理）

### 版本策略
- 所有医院运行同一标准产物；实施资料库维护**装机登记表**：院名 ｜ 版本 ｜ 配置 JSON ｜ 适配器实现及版本 ｜ impl 模块 ｜ 联系人
- 新版本发布后**逐院滚动升级**，先升试点院观察再推其余

### 升级流程（每院独立执行，约 15 分钟停机窗口）
```
停服 → 备份库(db-backup) → 换 jar+dist → 启动(Flyway 自动前滚) → 回归抽查(核心 E2E) → 失败则备份恢复回滚
```
配置、字典、规则库、impl 段迁移全在数据库里，产物替换动不到它们（四层模型的升级红利）。
有 impl 模块的医院：升级前先在实施仓库对新版重编译 impl，编译失败即兼容性破裂信号，先修再上。

### 问题分层归位（运行期铁律）
每个反馈先判层再动手：**改配置（当场生效）→ 换数据/规则（当场生效）→ 适配器缺陷（改实现包，同省同修）→
平台缺陷（提产品需求进版本，所有医院受益）→ 真定制（进该院 impl 模块）**。禁止为单院改平台核心。

## 四、上线前检查清单（逐项打勾）

- [ ] `HIP_JWT_SECRET` 已设置（非开发占位值）
- [ ] init-hospital 执行成功，admin 口令已更换（admin123 登录须返回 1001）
- [ ] 未采购模块已关闭（直连 API 实测 404）
- [ ] 字典导入完成，医保对照率达标（管理页可查）
- [ ] 生产库**未**运行过 bootstrap-demo（无 Demo1234 账号）
- [ ] 备份任务计划已注册且完成一次恢复演练
- [ ] HTTPS 生效；8080/5432 不对院外网开放
- [ ] 8 角色账号各登录一次，菜单与其职责相符
- [ ] 接口调研表归档；已接适配器跑通对账/回传实测

## 五、常见问题

| 现象 | 处置 |
|---|---|
| 启动即失败 | 查 Flyway 日志；确认库空或版本连续；实施段仅允许 V10000+ |
| 登录 401/1001 | 口令已被 init 更换，用配置里的新口令；连错 5 次锁 15 分钟 |
| 某模块整页消失 | 检查 `module.*.enabled` 配置——可能实施时按未采购关闭 |
| 医保对账有差异 | 看故障工单差异单号；核对适配器留痕是否符合 ADR-0002 关键字约定 |
| 检验结果未自动回传 | 集成监控查 ORU 报文；MLLP 端口连通性；OBR-2 须为申请单号 |
| 升级后 impl 接口报错 | 实施仓库对新版重编译 impl 模块，按 ADR-0003 修兼容 |
