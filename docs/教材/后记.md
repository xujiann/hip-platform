# 后记

这本书不是先有提纲再找例子写成的，而是从一个真实系统里"长"出来的。

它的源头是一个具体得不能再具体的工程任务：为县市级综合医院做一套买得起、跑得动、接得上医保的一体化信息平台。从第一张患者建档表到医保费用分割引擎，从深夜排查一笔对不平的结算差异，到用一所"虚拟医院"从零装机彩排整个实施流程——平台迭代到 v1.0.0 定版时回头看，那些反复出现的问题与反复奏效的解法，已经自己排成了一本书的目录。我要做的只是把它们如实写下来。

"如实"二字，是写作全程唯一的纪律，也是最难的部分。写书的人天然想把系统写得比实际更完整、把决策写得比当时更英明。本书选择了另一条路：**以代码为最终事实**。宣传口径与代码不符的，按代码写；文档声称有而代码没有的，写"规划与落地的差距"；当时判断失误造成返工的，把返工过程原样呈现。书中那些"教训案例"——被丢弃的冲正返回值、没地方存的医保结算号、抓不全增量的水位线——都曾是真实的深夜与冷汗。把它们印在书里，比印十条最佳实践更有价值，因为读者迟早会在自己的系统里遇见它们。

写作过程本身也是一次对平台的全面审计。为了确保每个案例可对照源码，全书的类名、表名、字段名都经过逐一核对；这个过程反过来揪出了平台里十几处文档与代码不符、乃至若干处真实的并发与安全缺陷——它们已进入修复流程。如果说这本书对 HIP 平台有什么回馈，这份"以写促审"的问题清单算是其中之一。

本书的写作与排版依托了一条完全开源可复现的工具链：Markdown 书稿、Mermaid 制图、Pandoc 转换、Typst 排版；平台本身则站在 Java、Spring Boot、Vue、PostgreSQL 及整个开源生态的肩膀上。向这些工具背后的社区致意。

书中仍有约六十处标注【成稿核对】的政策文号与标准条目待正式出版前逐条核定，也一定还有作者未能自察的错漏。医院信息化是一个政策、技术与临床三线并进的领域，书出版之日就是内容开始过时之时——唯愿书中那些不随版本更迭的东西：对业务的敬畏、对一致性的执着、对"如实"的坚持，能比具体的技术细节活得更久。

欢迎批评指正。
