# 附录 B 实训环境搭建指南

> 本附录面向使用本书开课的院校与培训机构：在一台普通机器上搭起完整的 HIP 平台，初始化一所虚拟医院，跑通一条门诊全流程，并把各章的实践题落到实处。装机细节以 [部署手册](../部署手册.md) 与 [多医院部署操作指南](../多医院部署操作指南.md) 为准，本附录只写实训场景的关键节点与常见坑。

## B.1 环境要求

单机即可完成全书实验（后端 + 数据库 + 前端同机），建议内存 8GB 起。两种组织方式：教师机集中部署、学员浏览器访问（省事，适合业务章节）；或每组一套独立实例（必需，适合第 4、5、14 章要动源码与数据库的实验——一院一实例一库本就是产品的部署形态）。

| 软件 | 版本 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 或 Linux | 生产形态为 Linux/信创麒麟，实训 Windows 即可 |
| JDK | **21**（Temurin） | 平台为 Java 21 + Spring Boot 3.5.5（勿用 17，编译不过） |
| Maven | 3.9+ | 构建后端多模块工程 |
| PostgreSQL | **16** | Docker、WSL 或系统安装三选一 |
| Node.js | LTS 版本 | 仅前端开发/构建期需要（Vue 3 + Vite） |
| Python | 3.10+ | 初始化工具与 E2E 回归脚本（仅标准库，无需 pip 依赖） |
| ai-service | 可选 | FastAPI（`pip install fastapi uvicorn`），缺席自动降级，不影响任何实验 |

## B.2 装机步骤与常见坑

按 [README](../../README.md)「本地启动」三步走：起 PostgreSQL → `mvn -pl server -am spring-boot:run` → `cd frontend/shell && npm install && npm run dev`，浏览器打开 `http://localhost:5173`，admin/admin123 登录。关键节点与坑：

1. **数据库先行且库要空**。建库 `hip`、用户 `hip`；首次启动 Flyway 自动执行全部迁移（V1–V43，含平台必需与行业基线种子）并创建 admin/admin123。启动即失败十有八九是库不空或迁移版本不连续——实训中"推倒重来"的正确姿势是删库重建，让 Flyway 重跑，而不是手工补表；
2. **Windows 下 Docker Desktop 不稳时用 WSL PostgreSQL**（仓库开发即此形态，`tools\dev-start.ps1` 一键起）；Linux 直接 `cd deploy && docker compose up -d`；
3. **端口清单**：后端 8080、前端开发 5173、MLLP 设备模拟 2575、ai-service 8100、Orthanc/PACS 8042。教学机房如有端口管控需提前报备；
4. **登录锁定**：密码连错 5 次锁 15 分钟——演示"防爆破"很直观，但学员集体输错时请等待或换账号，平台无解锁后门；
5. **JWT 密钥**：未设 `HIP_JWT_SECRET` 时回落开发占位值，实训可接受；借实训环境向学员演示第 13 章安全基线时，应现场设置一次并说明"生产严禁占位值"。

## B.3 初始化一所虚拟医院

实训环境走两条路线，对应两个教学目的：

**快路线（业务实验用）**：后端启动后执行 `python tools/bootstrap-demo.py`——幂等注入演示患者、8 角色演示账号（统一密码 Demo1234）、体检套餐等引导数据，配合 [培训脚本](../培训脚本.md) 即可分角色开练。注意此脚本**仅限实训/演示库**，生产库严禁运行（上线检查清单专门查它）。

**工艺路线（第 14 章实验用）**：用生产同款初始化工具 [init-hospital.py](../../tools/init-hospital.py) 走一遍真实施：复制 `tools/init-templates/hospital.example.json`，填写院名、模块开关（六域：drg/cdss/insurance/blood/hr/surgery）、科室与病区床位（NURSING 类型自动建床）、业务账号、药品/收费项目/医保对照三张字典 CSV，然后 `python tools/init-hospital.py 配置.json`。工具依次完成登录→机构配置→模块开关→科室床位→账号→字典导入→**强制更换 admin 口令**七步，幂等可重复。给虚拟医院起个像样的名字——院名会联动登录页、票据抬头与患者端，学员能直观看到"配置优先"的含义。

## B.4 验证清单：跑通一条门诊全流程

装机与初始化完成后，手工走通下表（对应第 2 章业务链与第 7 章各节），全绿即环境可用：

| # | 步骤 | 入口 | 预期 |
|---|---|---|---|
| 1 | 患者建档 | 患者管理 | 身份证号自动推算性别生日；同证件号重复建档幂等返回原档 |
| 2 | 排班与挂号 | 门诊挂号 | 选号源挂号成功；余号减一，满号拦截 |
| 3 | 收挂号费 | 门诊收费 | 挂号费自动并入待收（REG 订单行） |
| 4 | 接诊与病历 | 门诊医生站 | 候诊列表见患者；病历保存后出现 CDSS 建议条 |
| 5 | 开单 | 医生站处方/检验 | 开一条药品 + 一条血常规；试开"头孢+藿香正气"体验配伍拦截（4015） |
| 6 | 收费 | 门诊收费 | 订单转已收费；选医保支付可观察费用分割明细 |
| 7 | 检验执行 | LIS 工作台 | 采样打码→核收→录入结果发布；录 HH 值触发危急值弹窗，医生站须确认 |
| 8 | 发药 | 药房发药 | 发药成功、库存核减；重复发药被拦 |
| 9 | 患者端 | /portal | 患者号+手机号登录，可见挂号、报告（危急值遮蔽为回院提示）、智能导诊 |

自动化对照：`python tools/e2e-outpatient.py` 覆盖同一闭环外加退费/退号拦截等分支，30 秒内应全部通过。E2E 脚本本身就是教材——每个断言都是一条业务规则（第 13 章 13.6）。
