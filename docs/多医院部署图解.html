1部署形态：一院一实例

铁律：全部医院运行同一个标准发布产物；每院独立实例、独立数据库（院内网）。 医院差异只存在于三处：配置数据、适配器实现、impl 定制模块。标准核心永不分叉。

2平台功能地图（55 个功能页）

八大业务域 + 患者端；带 ⏻ 标记的六个模块可按院整体关闭（第 3 节）。完整逐页能力见 docs/功能清单.md。

3按院取舍：模块开关矩阵

六个功能域支持整体启停：一个配置键，菜单入口与后端接口同时关闭（直连 URL 也进不去）。

4单院实施七步

每家新医院重复同一条流水线；①–⑤ 技术实施，⑥–⑦ 进入运行期。全程有工具、有模板、有检查清单。

5一键初始化机制

每院一份配置 JSON 描述「这家医院长什么样」，init-hospital 工具照单执行，幂等可重复。

6接口适配：换实现不换平台

医院间最硬的差异是对外对接（各省医保、各厂设备与 CA）。平台把每类差异收敛为一个接口，实施时只替换实现。

7多院版本管理与升级

装机登记表记录每院版本与差异件；新版本先升试点院观察，再逐院滚动，每院约 15 分钟停机窗口。

8运行期铁律：问题分层归位

多院运行后，每一条反馈先判层再动手——这是保持「永不分叉」的日常纪律。

9上线检查清单与文档体系

上线前逐项打勾

  • JWT 密钥已用环境变量注入（非开发占位值）
  • init-hospital 执行成功；admin 旧口令登录被拒（1001）
  • 未采购模块已关闭，直连 API 实测 404
  • 字典导入完成，医保对照率达标
  • 生产库无演示账号（未运行 bootstrap-demo）
  • 备份任务已注册并完成一次恢复演练
  • HTTPS 生效；应用与数据库端口不对院外开放
  • 8 角色账号各登录一次，菜单与职责相符
  • 接口调研表归档；已接适配器实测通过
