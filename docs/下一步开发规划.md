## 二、下一步规划（第四期起，每期约 6-8 周）

### 第四期「门诊闭环补强 + 患者流」← 建议立即开工
优先补齐日常运营高频缺口，均可独立验证、无外部依赖：

1. **门诊护士站(44)**：输液/注射执行（TREAT 订单执行界面）、皮试登记
2. **叫号四件套(33-36)**：挂号即入队，医生站接诊触发叫号；诊室/药房/检查检验共用队列引擎 + 大屏页
3. **检查检验预约(37/38)**：申请单开出后选时段，医技端按预约队列执行
4. **住院转科转床**：补齐入出转的「转」
5. **CA 电子签名(10) 预留落地**：病历/处方签名接口 SPI + Mock（同医保适配器模式），签名后病历版本冻结
6. **病案统计基础(75)**：病案首页数据结构 + 出院病历归档状态流

### 第五期「药事智能 + 病历质控」（评级要件）
电子病历 4 级评价的核心功能：

1. **合理用药基础(5/77)**：过敏史拦截、重复用药、抗菌药物分级权限（规则引擎起步）
2. **处方点评(7) + 智能审方(9)**：药师审方队列（处方开出→审核→收费），点评抽样与统计
3. **病历质控(74)**：时限质控（24h 内完成入院记录等）+ 缺陷评分
4. **CDSS 起步(32)**：诊断-用药知识提示（知识库(6)最小集）
5. **电子病历全文检索(71)**：接入 Elasticsearch（CDR 文档索引化）

### 第六期「管理决策 + 医保」
1. **DRG 管理(1)**：分组器接入（先用公开分组规则）、病组成本分析
2. **医保智能审核(2)**：事前提醒规则（超适应症/超量）
3. **公立医院绩效考核(19) / 评审指标(18)**：指标计算引擎，从 CDR/ODR 取数
4. **运营数据中心(13) + 数据质量(14)**：CDR 扩展为 ODR，CDC 增量同步替代全量抽取
5. **真实医保 SDK 适配**（需医保局环境配合）

### 第七期「HRP 运营」
财务对账(92)、物资(94)、设备(95)、高低值耗材(96/97)、固资(98)、OA(101)——复用进销存模型扩展；人事(93)、消毒供应(99)、供应商(100)按需排期。

### 第八期「专科与影像」（需设备/算法生态配合）
急诊系列(66-70)、手麻(54)、ICU(55)、体检(59)、LIS 本体(56)、RIS/PACS(62/63，可集成 Orthanc)、云胶片(41)、AI 阅片(3，Python 子服务)、心电(4)、移动医护(60/61)。

### 持续性工作（每期附带）
- 微信公众号(105)/APP(104)：patrol H5 已具备内核，待微信资质接入实名
- 术语标准化(26)/结构化文档(27)：CDA/WS 500 格式化输出
- 测试覆盖率提升 + E2E 纳入 CI（需 Actions 内起完整后端）

## 三、优先级依据

1. **第四期选题标准**：医院日常运营每天都用（护士站/叫号/预约）+ 补主线残缺（转科/CA/病案）——这是试点医院能否真实运转的门槛
2. **第五期对准电子病历分级评价 4 级**：合理用药、审方、质控是评级硬指标
3. **第六期对准管理层价值**：DRG/医保/绩效是院长最关心的回报点
4. HRP 与专科放后：可独立采购/集成第三方，不阻塞主线
