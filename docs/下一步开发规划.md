# 采购需求覆盖盘点与下一步规划（v5）

> 基准：《采购需求》107 模块 / 4298 条参数 ｜ 更新：2026-08-04（一至十七期完成后）
> 现状：12 后端模块、17 Flyway 版本、44 页面、32 测试、10 套 E2E、CI 三任务（单测/前端/完整后端 E2E）全绿

## 一、盘点

**已完成**：需求中软件可实现项全部落地 + 落地配套（打印/日结/等保/迁移工具/压测/部署手册）+ 验收工具（参数矩阵）+ 三层质量防护网（单测/E2E/云端 CI）。

**剩余工作四类**：

1. **工程债**（十七期明确缓期）：九至十六期 JdbcTemplate 聚合层下沉独立模块
2. **通用化差距**（新识别）：平台定位通用产品，但患者端登录页、打印单据等处仍硬编码具体医院名称；机构信息未参数化
3. **可自建深化**：CDA 标准输出、全文检索、CDC 增量、Orthanc 影像、AI 子服务骨架
4. **外部条件项与交付工程**：医保/微信/CA/设备对接；参数评定、手册、实施演练

## 二、下一步计划

### 第十八期「架构还债 + 产品通用化」← 建议下一步（新会话执行）
1. **聚合层下沉**：护理质控/患者管理/HRP 扩展/数据治理/医技本体五组 JdbcTemplate 控制器按域下沉独立模块（十七期缓期项，大面积重构须干净上下文）
2. **机构参数化**：新增系统参数表（医院名称/简称/票据抬头/联系方式），清理患者端与打印页的硬编码院名，所有单据与页面从配置读取——通用产品的门槛项
3. **演示数据开关**：种子数据拆分为「必需字典」与「演示数据」两组迁移，交付新医院时可跳过演示组
4. **静态检查进 CI**（十七期未竟项）

### 第十九期「标准与互操作」
CDA（WS/T 500）文档输出、OpenSearch 全文检索（CDR 索引化）、CDR 抽取改 updated_at 水位增量。

### 第二十期「影像与 AI 自建部分」
Orthanc 部署 + DICOM 上传/Web 调阅 + 报告关联影像（云胶片雏形）；Python FastAPI AI 子服务骨架（mock 阅片/CDSS，真实模型即插即用）。

### 第二十一期「验收与实施冲刺」（交付工程）
参数矩阵 4062 条分域评定（AI 初评+人工复核）→ 技术偏离表；分角色操作手册与培训课件；脱敏数据迁移演练 ×2。

### 外部条件触发项（不占期序）
医保 SDK（InsuranceAdapter）、CA（SignatureAdapter）、微信（portal 嵌入+实名）、LIS/PACS 设备（MLLP 2575）、AI 算法（子服务位）。

## 三、判断依据

- 十八期把「工程债 + 通用化」合并为一期：两者都是改造存量而非新增功能，合并可一次回归验证；通用化是产品能否交付第二家医院的门槛
- 此后每期收窄为单一主题，避免大 batch 带来的回归面扩大
