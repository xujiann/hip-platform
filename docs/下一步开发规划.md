# 采购需求覆盖盘点与下一步规划（v6）

> 基准：《采购需求》107 模块 / 4298 条参数 / 商务要求 ｜ 更新：2026-08-04（一至二十一期完成后）
> 现状：13 后端模块 + AI 子服务 + Orthanc、18 个 Flyway 版本、32 测试、11 套 E2E、CI 三任务全绿

## 一、盘点：视角从「功能清单」转向「商务条款」

功能维度：107 项中可自建项已全部落地（含机构参数化后的通用产品形态）。**尚未覆盖的是需求商务要求隐含的运维保障能力**——服务期年度考核规定：

- 性能表现 40 分：年故障 ≤5 次且 30 分钟内解决，软件重大事故一票归零
- 技术支持 30 分：1 小时响应、24 小时解决；巡检 ≥2 次/年

要拿住这 70 分，平台必须自带：故障可发现（监控告警）、可恢复（备份回滚）、可举证（运行台账）。当前这三样都没有。

## 二、下一步计划

### 第二十二期「运维保障体系」← 建议下一步（直接对准考核 70 分）
1. **全栈容器化**：后端 Dockerfile + compose 增加 app/前端 nginx 服务，一键起完整栈（当前 compose 只有数据库）；CI 增加镜像构建
2. **自动备份**：pg_dump 定时任务（每日全量 + 保留 N 天策略）、恢复演练脚本——「可恢复」
3. **健康监控与告警**：定时探测（应用 health/数据库/MLLP/AI 子服务/PACS），异常写告警台账并支持 webhook 外发——「可发现」
4. **运行台账**：故障登记/处置/恢复时长记录（对准「30 分钟解决」举证）、巡检记录——「可举证」，年度考核的原始凭据
5. **慢接口观测**：审计日志增加耗时字段，日结慢接口 TOP 榜

### 第二十三期「参数矩阵人工复核批次」（AI 辅助，分批新会话）
997 条「待人工评估」按 8 大域分批，每批新会话对照代码逐条精评（符合/部分/偏离+依据），累计产出正式《技术偏离表》。26 条涉外部条件项单列说明。每批约 120 条，预计 8 个批次会话。

## 三、判断依据

平台的「建设阶段」已结束，进入「可运营阶段」的建设：二十二期产出的不是业务功能，而是让系统能在真实医院 7×24 跑下去并通过年度考核的基础设施——这是需求商务条款的刚性要求，也是所有后续试点的前置。
