# 采购需求覆盖盘点与下一步开发规划（v2）

> 基准：《采购需求》107 模块 ｜ 更新：2026-08-04（一至八期完成后）
> 平台现状：11 后端模块、15 Flyway 版本、31 页面、8 套 E2E + 22 测试、CI 全绿

## 一、覆盖现状

**已实现（MVP 及以上，约 35 项）**：门诊全线（挂号/医生站/病历+签名/收费退费/发药退药/医技执行/叫号/审方/预检分诊）、住院全线（入出转/医嘱/护士执行/病历体征/出院结算）、药事（药房/药库进销存/合理用药拦截）、平台底座（RBAC/EMPI/主数据/集成引擎 HL7+MLLP+医保 SPI/CDR/危急值）、患者端 H5、驾驶舱与运营指标（含病组分析雏形）、固资台账。

**未实现约 70 项**，按可推进性分两类：

- **纯软件可继续**（无外部依赖，约 40 项）：护理文书类、质控管理类、数据中台类、HRP 扩展、随访满意度、临床路径、会诊、体检等
- **需外部条件**（约 30 项）：真实医保 SDK、微信公众号/APP 资质、CA 厂商、LIS/PACS/超声/内镜/心电设备、AI 阅片算法、DRG 官方分组器、电子健康卡省平台

## 二、下一步计划

### 第九期「护理与病历质控」（建议下一步，评级要件）
1. **护理病历(51) + 护理白板(79)**：护理记录单（分级护理、出入量）、病区白板（在院一览：床位/护理级别/过敏/待办）
2. **电子病历时限质控(74)**：规则引擎——入院 24h 内完成入院记录、病程 3 日一记、出院 24h 出院小结；缺陷清单与科室评分
3. **病案首页(75)**：出院病案首页数据集（诊断/手术/费用汇总自动带入）+ 归档状态流
4. **不良事件上报(82)**：事件分类分级上报、处理流转、匿名上报
5. **院感监测基础(80)**：感染病例登记 + 抗菌药物使用天数统计（DDD 雏形）

### 第十期「患者管理闭环」
1. **患者随访(39)**：出院/门诊随访计划、到期任务队列、随访记录（患者端 H5 同步可见）
2. **满意度调查(42)**：问卷模板、患者端填写、科室统计
3. **临床路径(53) 基础**：路径模板（按病种定义医嘱套餐+变异记录）、入径/出径
4. **院内会诊(58)**：会诊申请→应邀→意见书写闭环
5. **健康体检(59) 基础**：套餐定义、登记、汇总报告

### 第十一期「HRP 扩展」
物资(94)/设备(95)/高低值耗材(96/97) 进销存（复用 inv 流水模型泛化为多类目库存）、供应商台账(100)、OA 通用审批流(101)（请假/用章/采购申请）。财务(92)/人事(93) 按需排期或集成第三方。

### 第十二期「数据中台完整化」
数据填报与审批(17)、指标标准管理(15)（指标定义→自动计算→驾驶舱）、数据标准/数据元(16/24)、数据质量(14)（完整性/及时性核查任务）、运营数据中心(13)（CDR→ODR 扩展 + CDC 增量同步替代全量抽取）、报表引擎（自定义报表导出）。

### 外部条件到位即插入的对接战役（不占期序）
| 条件 | 战役 | 平台已备好的接入点 |
|---|---|---|
| 医保局测试环境 | 真实医保结算 | InsuranceAdapter SPI 直接替换 Mock |
| 微信公众号资质 | 公众号/实名 | portal H5 整体嵌入 + 登录换实名通道 |
| CA 厂商 SDK | 合规电子签名 | SignatureAdapter SPI 直接替换 Mock |
| LIS/PACS 设备 | 设备直连 | MLLP 2575 端口 + ORU 处理链路现成 |
| AI 算法服务 | AI 阅片/CDSS | 规划的 Python FastAPI 子服务位 |

### 工程持续项（每期附带）
测试覆盖率提升（新模块补单测）、E2E 纳入 CI（Actions 内起完整后端）、全文检索（WSL 装 OpenSearch 后接 CDR）、性能压测基线。

## 三、建议

下一步开工**第九期**：五个功能全部无外部依赖、直接对准电子病历分级评价与三级医院评审的护理/质控硬指标，且能让试点医院的护理团队真正用起来——这是目前平台「医生用得多、护士用得少」短板的针对性补强。
