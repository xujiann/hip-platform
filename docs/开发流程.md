# 开发流程（防迷路手册）

> 写作背景（2026-09-11）：平台已 40+ 发布版本、59 轮规划、44 套 E2E，且多会话并行开发是常态。
> 迷路的根源不是没有流程，而是流程只存在于惯例里。本文把已被 v57–v59 反复验证的惯例成文，
> 回答两个问题：**「我现在在哪」**（§〇）与**「下一步按什么走」**（§二）。
> 原则：状态一律从 git 与文档推导，不靠人记；数字类事实只有一个事实源（§五）。

## 〇、迷路恢复协议（30 秒定位，任何会话开工前先走一遍）

1. `git log --oneline -15` —— **提交前缀就是状态机**（对照 §二 表）：
   最近一条是 `vNN 车道X` → 该轮车道实施中；`vNN 审阅修补` → 审阅回路中；
   `X.Y.Z vNN ...` → 该轮已定版；`签认清单/复核` 类 → 验收回路中。
2. 打开 [下一步开发规划.md](下一步开发规划.md) **最顶节** —— 即当前规划轮。
   节标题带「已发 vX.Y.Z」= 该轮已收口；没带 = 进行中，节内车道表就是任务清单。
3. `docs/验收/` 按文件名取最新 vNN 的核账/复核文件 —— 看**打回清单是否清零**；
   未清零的条目就是下一轮的立项输入，不需要重新想「接下来做什么」。
4. `git tag --sort=-creatordate`（取前 3）对照 CHANGELOG 顶部版本号 ——
   **tag 落后于 CHANGELOG = 定版检查单（§三）没走完**，先补齐欠账再开新工。
5. 多会话并行提醒：接手前确认其它会话是否在途（同车道文件、8080 端口占用）；
   车道各自 worktree，勿在主工作区重复提交他会话在途工作。

## 一、三套编号（迷路的第一根源，先分清）

| 形如 | 含义 | 节奏 | 事实源 |
|---|---|---|---|
| **vNN**（v59） | 规划轮：一轮「发现 → 修复 → 复核」 | 高峰期一天 1–2 轮 | 规划文档节标题、提交前缀 |
| **vX.Y.Z**（1.5.9） | 发布版本：一次交付定版 | 与规划轮一对一 | CHANGELOG、git tag |
| **VNNN**（V166） | Flyway 迁移：一次数据库变更 | 一版可含多个 | `db/migration/`，规划节统一发号 |

同样需要集中预分配的还有：错误码段（[错误码分段.md](错误码分段.md)，先查后登记，已撞码多起）、
菜单 id、sys_config / gate 键——全部在规划节「前置发号」处列出，**车道内不得自造编号**。

## 二、一轮的标准流程（九步，提交前缀即状态）

进入第 1 步的来源四选一：**全库审阅轮**（六轮先例）／**核账**（回查投标应答与偏离表，
诚信纪律见 §四）／**上一轮复核打回清单**／**试点运行反馈**。

| # | 步骤 | 动作要点 | 产物 / 提交前缀 |
|---|---|---|---|
| 1 | 立项切版 | 在规划文档**顶部**新增 vNN 节；**一版只承担一类风险**（纯新增隔离与改既有写路径分开成版）；写明**「范围外」红线**防实现者顺手越界 | 规划节（含范围外声明） |
| 2 | 前置发号 | 错误码（查分段→登记）、迁移号、菜单 id、sys_config/gate 键，集中预分配并锁定口径 | `vNN 前置：锁 ...` |
| 3 | 车道划分 | A/B/C/D… 并行；**文件独占表**写进规划节（谁独占 PrintView，谁独占医生站页）；跨车道公共文件（router/index.ts、sys_menu 种子）**合版统一改**，车道只用预分配 id | 规划节车道纪律 |
| 4 | 还测试欠账 | 动零覆盖域之前**先补锁定既有行为的单测**，再写新代码——改写路径时唯一的安全网 | 车道首个提交 |
| 5 | 车道实施 | 每车道一个关注点；**核账车道惯例 = `e2e-vNN-audit.py` 分段断言 + 挂 CI**，把本轮口径钉进回归 | `vNN 车道X：...` |
| 6 | 合并补齐 | 清扫车道清单外的联动处：中文名/枚举映射/过时注释/既有测试期望随新契约更新 | `vNN 合并后补齐：...` |
| 7 | 审阅 | 车道审阅（low 扫一遍 + 重点车道 medium）；修补单独成提交，写清「审阅者原话 → 修法」 | `vNN 审阅修补：...` |
| 8 | 定版 | 逐项过 §三 检查单 | `X.Y.Z vNN ...` + tag |
| 9 | 复核回路 | 核账/复核文件入 `docs/验收/`；偏离表逐条**上调/维持**留痕；**打回清单未清零项 = 下一轮第 1 步的输入** | `docs/验收/vNN复核-*.md` |

## 三、定版检查单（第 8 步逐项过，缺一即未定版）

- [ ] 全量 `mvn clean package`（改多模块不带 `-am` 会打进旧模块；旧进程占 jar 时 clean 静默失败，先杀进程）
- [ ] **全新库**按 CI 顺序全量 E2E（方法论⑦——本地历史库会掩盖断裂）
- [ ] 换包后 `curl /actuator/info` 比对 build.version（方法论⑥——health UP 会说谎）
- [ ] 浏览器实测本轮演示路径（E2E 不覆盖交互细节，双击/模态/翻页类问题只有手点能发现）
- [ ] CHANGELOG 新节与 **git tag vX.Y.Z 同时落**，谁也不欠谁
- [ ] 文档联动：错误码速查表／配置手册键数／培训脚本「⚠ 新」标记／README 统计数字
- [ ] 规划节标题回填「已发 vX.Y.Z」+ 交付实测数字（测试数/E2E 套数/错误码数——只在此刻写）
- [ ] 新债入 [技术债交接单.md](技术债交接单.md) 文末待议区

## 四、纪律引用（内容在各自文档，此处只指路）

| 时机 | 必读 | 一句话 |
|---|---|---|
| 写测试/做验证前 | [测试方法论.md](测试方法论.md) | 九条实付学费；违反任何一条的「绿」都可能是假绿 |
| 发新错误码前 | [错误码分段.md](错误码分段.md) | 先查分段再登记，口口相传已被证明失效 |
| 动种子数据前 | [种子数据分层清单.md](种子数据分层清单.md)「测试契约」节 | 有些种子被测试硬引用，动之前先查 |
| 核账/回查应答时 | 诚信处置纪律 | 应答「已实现」而代码没有 → **补真实现，或下调偏离并在签认清单登记理由，不得维持现状**；HQMS／医保结算清单／财政电子票据三条外部边界**禁止假实现** |
| 写源码扫描类测试时 | v58 车道 D 教训 | 排除路径一律用**仓库相对路径**——绝对路径在 worktree 下扫空恒绿 |

## 五、防漂移守则（让流程自身不再制造迷路）

- **数字类事实单一事实源**：测试数、E2E 套数、错误码数只在定版时点写进规划节与 README，
  平时不更新、其他文档不复述数字（复述一次就多一处过期源）。
- **规划文档只在顶部追加**；旧节是历史存档，不改写、不重排——「找现状读顶节」这条捷径
  依赖此约定成立。
- 本文档只在**流程真的变化**时修改；文中例子（v58/v59）过时不影响规则成立，不为追新而改。
