# ADR-0003 实施定制层（L4）规约

- 状态：已接受（2026-08-06，产品化一期）
- 背景：标准产品 + 实施个性化的四层模型（docs/产品化方案.md）要求真定制有隔离的落点，
  不 fork 平台核心、不阻碍版本升级。模板见 `impl/template-hospital/`。

## 规约

1. **代码位置**：每院一个 Maven 模块 `impl/<hospital>`，parent 指向 `hip-parent`，
   包名 `cn.hip.impl.<hospital>.*`——启动器 `scanBasePackages=cn.hip` 自动装配，无需改平台代码。
2. **启用方式**：根 pom `<modules>` 加入该模块 + server pom 加依赖（这两行是**实施仓库**的改动；
   标准仓库的根 pom 永远不含任何 impl 模块）。
3. **数据库**：仅使用 Flyway **V10000+ 版本段**（平台保留 V1–V999）；迁移文件放本模块
   `src/main/resources/db/migration/`（Flyway 默认扫描全 classpath，同库合并执行、版本互不冲突）。
   只允许创建 `impl_` 前缀自有表；**禁止**修改平台表结构（升级兼容底线）。需要平台数据时读平台表、写自己的表。
4. **接口**：定制 API 走 `/api/impl/<hospital>/**` 前缀；权限注解自管；错误码使用 20000+ 段避开平台段。
5. **前端**：定制页面放实施仓库独立目录，路由走 `/impl/*` 前缀懒加载；不改平台页面源码。
6. **升级**：平台升级 = 换标准产物 → impl 模块随实施仓库重编译验证兼容 → Flyway 各段自动前滚。
   若 impl 编译失败即为兼容性破裂信号，先修 impl 再上线。

## 模板内容（impl/template-hospital）

- `pom.xml`：artifactId `hip-impl-template`，依赖 hip-platform-core
- `TemplateImplController`：`GET /api/impl/template/ping` 示例（含 ADMIN 权限注解）
- `V10000__impl_template_init.sql`：建 `impl_template_note` 示例表
- 默认**不**挂入根 pom——标准构建不包含任何 impl 代码；三期彩排时以副本形式启用验证
