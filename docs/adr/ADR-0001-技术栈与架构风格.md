# ADR-0001 技术栈与架构风格

日期：2026-08-04 ｜ 状态：已采纳

## 背景

通用医院信息化平台（对标 107 模块采购需求），小团队 + AI 辅助开发，目标客户为县级/地市二级医院，内网部署、运维力量薄弱，未来可能有信创要求。

## 决策

1. **主业务**：Java 21 + Spring Boot 3.5，Maven 多模块**模块化单体**；模块间仅通过接口与事件通信，保留微服务拆分口。
2. **AI 子服务**：Python FastAPI 独立部署（阅片/NLP/智能审核），通过 REST 接入，故障不影响主业务。
3. **前端**：Vue 3 + TypeScript + Element Plus，单一工作台外壳，后续按微前端（qiankun）拆分模块。
4. **数据库**：PostgreSQL 16 单主库 + 按模块 schema 隔离；缓存 Redis；信创场景平移达梦/金仓。
5. **数据库演进**：Flyway 管理 DDL，JPA `ddl-auto=validate`（禁止 Hibernate 自动建表）。
6. **认证**：无状态 JWT + RBAC（用户-角色-菜单/权限点）。

## 备选与否决理由

- .NET 8：工程质量同级，但国内 HIS 生态、医保/设备 SDK、招聘池均弱于 Java 一档，仅在团队 C# 明显更强时才值得。
- Python/Node 做主业务：强事务大规模代码库的长期维护成本高，医院内网离线部署不友好，否决。
- 微服务起步：县级医院 2–4 台服务器、无 DevOps 团队，分布式复杂度不可接受，否决。

## 影响

- 所有业务模块以 Maven module 形式加入 `modules/`，由 `server` 聚合启动。
- 需要在第 1–2 迭代内定义模块间通信规范（Spring 事件 + 接口 SPI），防止模块间直接引用 Repository。
