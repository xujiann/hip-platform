## 总体判断

业务闭环质量良好，缺陷集中在两个系统性方向：

1. **「读-判-写」代替原子操作**——1.0.2 修过同一家族（处方号/退药/占床），当时只覆盖门诊三处，
   同族漏网点仍有十余处（住院组号、医嘱执行、结算、退费、转床、入库、盘点、叫号、审方…）
2. **安全防线只做在 UI 与主路径**——API 直连时权限、幂等、渠道校验均不存在

## P2 值得做（不阻塞试点，排后续版本）

- **全仓无 `@RestControllerAdvice`**：BizException/InpException/DataIntegrityViolation/NumberFormat 一律 500，
  前端拿不到业务码——**这是上述多条问题严重度的共同放大器**，建议优先于其他 P2
- **审计过滤器排在安全链之后**（`AuditLogFilter` 无 `FilterRegistrationBean`/`@Order`）：401/403 越权请求不入审计，
  等保"失败访问留痕"落空；且只记写操作，敏感读（患者列表/CDA/CDR 检索）零留痕
- **MLLP**：字符集硬编码 UTF-8 不读 MSH-18（国产 LIS 发 GBK→中文结果乱码入库）；帧缓冲无上限+无界线程池+
  端口无鉴权（单连接可打爆堆）；`handle()` 只 catch IOException，留痕字段超长时异常逃逸致静默丢消息不回 ACK
- **HL7 进站端点无权限**（`Hl7InboundController.java:21-28`）：任意在职账号可伪造检验结果并触发危急值
- **sys_config 数值配置无校验**：`yb_ratio_staff` 填 1.5→医院倒贴；填 "abc"→全院医保结算 500
- **报告分享链接**：有效期无上限（可造百年外链）、创建无权限校验、无吊销端点
- **CdrSyncService.syncAll**：单事务全量 N+1 拉取（试点量即超时）；内容 `substring(0,7900)` 产出非法 JSON
- **跨控制器错误码复用**：9950 三处三义（MedTech/MedRecordStats/Ops）、9910 两处、9013/9014 同名双义、4510 同控制器双义
- 其他：默认口令 admin123 无强制改密、`@NotBlank` 未加 `@Valid` 全部失效、分享报告空字段 NPE 500、
  订阅 target_url 无白名单（接真实推送即 SSRF）、`lowStock` 全表载入内存、跨年瞬间年度额度记错年份、
  身份证校验位合法但日期非法→建档 500
