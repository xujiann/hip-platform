## 总体判断

前两轮共修 51 项，测试 114 + E2E 20 套 + CI 4 作业全绿。本轮缺陷的**性质变了**：
不再是"旧代码写错"，而是**上两轮修复的落地完整性**。四个同构形态：

1. **列建了没人读**——`refunded_at` 加了列、回填了数据、建了索引，**零查询引用**（C-5 判定为已修有误）
2. **索引建了查询不走**——1.1.1 的 `idx_outp_charge_created` 对 27 处 `created_at::date = ?` 全部不可 sarg
3. **顺序调了没跨过安全链**——审计过滤器 `@Order(30)` 仍在 Spring Security 链（-100）**之后**，
   401/403 依旧不入审计；1.1.1 只排了三个自定义过滤器彼此的顺序
4. **锁在连接池上不成立**——`pg_try_advisory_lock` 是会话级，而 JdbcTemplate 每次调用各借一条连接

其中第 4 项是本轮唯一的 P0 级新增风险，且**只在"任务体占用连接"时才暴露**——
空闲池单线程下表现完全正常。这正是上一轮总结的教训在新代码上的复现：
**验证正常路径会让错误的修复看起来是对的**。
