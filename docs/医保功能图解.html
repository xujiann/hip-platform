1能力总览与分层定位

医保域由七块能力组成，分布在标准化模型的三层：业务功能是标准产品，比例与目录是配置数据，真实通道是可替换的 SPI。

2目录对照

分割的前提是知道每个项目「医保怎么看它」：对应哪个国码、属于甲乙丙哪一类、乙类先自付多少。

3结算费用分割

医保结算时逐订单行自动执行：分类 → 计算可报销基数 → 乘统筹比例 → 汇总成统筹/个人两个口径，行级明细留痕。

4门诊医保结算通道

收费员选择 YB 支付方式后，一个事务里依次完成本地结算、分割审核、通道上传——上传失败则整笔回滚，不留悬账。

5退费冲正与住院医保

退费联动冲正报文；住院在出院结算时走同一适配器上传，失败同样阻断。

6智能审核雏形

三条本地规则在分割完成后同步触发，WARN 级留痕不阻断结算；表结构预留 BLOCK 级，为真实规则库接入留位。

7对账

按日逐单核对「业务账」与「通道账」：本地结算记录 ↔ 医保出站报文，差异定位到单，批次留痕。

8DRG 医保支付模拟

面向 DRG 付费改革的院内测算：出院病例自动入组，费率 × 权重得到标杆支付，结余与高低倍率一目了然。

9真实医保的替换路径

当前通道是 Mock 实现；接入真实医保 = 写一个省 SDK 版适配器实现类，业务侧零改动。

尚未覆盖（边界声明）

  • 外部条件项：电子医保凭证、异地就医备案与结算、医保移动支付——依赖医保局接口资质；
  • 配套产品项：商用审核规则库（申诉、飞检、大数据稽核）——yb_audit_log 同表扩展接入；
  • 后续增强：住院行级分割（当前总额口径）、目录对照批量导入模板。
