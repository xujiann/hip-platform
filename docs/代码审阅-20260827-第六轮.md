## P2（5 项，全闭环）

- **F2 改密端点是无节流口令预言机**：旧密校验不计数、不锁定、锁定期照改——1009 闸把被盗首登态 token 限死在这条路上，而这条路恰好不限速（实测 20 连猜零代价）。修：接入与 /login 同一套 `bumpFailedAttempts` + 锁定检查，回归锁定"5 次爆破后正确旧密也进不来"
- **V61 的 admin 兜底 UPDATE 恒不命中**：`password_updated_at = created_at` 永假（两列由不同迁移事务的 now() 写入，实测差 150ms）——"从未改密的 admin 首登强制"一次也没发生过。死代码带来虚假安全感；与既有取舍（处女库 admin 不置位）合并为明确行为，运维手册明示手工置位路径
- **前端"静默降级"不静默**：全局 axios 拦截器对模块开关 404 无条件弹红 toast，发生在组件 catch 之前——关 cdss 后接诊仍弹错、专科页双 toast。修：拦截器识别模块开关 404 跳过全局提示
- **demo-start 灌数据一步无 NativeCommandError 防护**（同文件 E2E 循环防了、bootstrap 没防——又是只落一侧）。修：同款防护
- **e2e-phase2931 硬编码 admin/admin123**：绕过 `HIP_E2E_PASSWORD` 覆盖机制，改密环境下恒失败且每次给 admin 记失败计数。修：走环境变量

## P3 / 裁决（要点）

- raceCount 白名单收 `Duplicate` 与方法论 ⑨ 自相矛盾（约束错兜底=防线失效被掩盖）→ 移除，锁类异常对称匹配
- Phase128 召回用例泄漏占用床（种子仅 10 张，约 5 轮耗尽）→ @AfterEach 归还
- ModuleToggleTest 缺 @AfterEach evictCache（方法论 ⑤）→ 补
- demo-start：-Fresh 空库校验 `[int]$null=0` 假绿 → 按退出码 + 严格字符串；WSL 保活进程累积泄漏 → 先查后起、-Stop 收掉
- demo-deploy：就绪循环双口令重试会把 admin 锁死 → 循环只试默认口令、目标口令单次判定
- bootstrap 改密闭环崩溃后不自愈 → 已存在账号探测 mustChangePassword 补闭环
- ModuleGate 豁免短路潜伏跨模块迭代序依赖 → 豁免只在命中本模块前缀时检查
- **iat 收窄兼容窗口（裁决：不采纳）**：思路成立但需整秒严格小于比较 + 引入多实例时钟偏差假杀风险——是换一种取舍而非消灭取舍；现设计的 12h 窗口仅为升级瞬时过渡，维持
- 多实例下 evictCache 仅本机生效（≤30s TTL 自愈）→ 已在多实例文档标注

## 方法论增量

- **审阅 agent 自己踩出的教训**：MockMvc + 手设 SecurityContext 不清理 → 过滤器外层门被残留登录态短路，整个 token 链被跳过，制造"闸没生效"的假象——与方法论 ④ 同源（线程/事务状态不自动归零），已入方法论
- 域②的验证纪律值得沉淀：**每条发现附运行实证**（AST 证死代码、探针库证迁移恒不命中、PS 5.1 实验证类型转换假绿），比"看起来有问题"高一个数量级
